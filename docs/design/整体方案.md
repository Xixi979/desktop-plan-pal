# 「桌面计划小人」整体方案与实现思路

> 定位一句话：一只住在桌面上的「计划小人」——你随手丢给它计划，它结合你的课表和精力强度，自动把时间排好，并在合适的时候提醒和陪伴你。
>
> 本文档以架构与思路为主，不含具体代码。面向后续开源准备。

---

## 一、产品定位与目标用户

### 1.1 产品定位

- **品类**：桌面宠物（陪伴层） × 自动排程引擎（功能层）的融合产品。
- **差异化**：市面上桌宠只有"萌"，只有提醒；日历工具只有"格子"，需要手动排。本产品把两者结合——**小人既是形象入口，也是排程结果的"执行者/监督者"**：它站在桌面上，指着日历告诉你"接下来该做高数了"。
- **核心体验闭环**：随手新增 → 自动录入 → 结合课表与强度约束自动排布 → 小人按时提醒/陪伴 → 完成后反馈，排程动态调整。

### 1.2 目标用户

| 人群 | 典型场景 | 核心诉求 |
|---|---|---|
| 大学生/考研党（首要） | 有固定课表 + 碎片化学习计划 | 不想手动排时间，希望按课表缝隙自动插学习块 |
| 备考/自律人群 | 高强度多科目任务 | 负荷上限可控，防止过度排程 |
| 自由职业/远程工作者 | 无固定课表，任务驱动 | 自动 time blocking，避免"什么时候做"的决策疲劳 |
| 桌宠爱好者（流量层） | 陪伴、情感化 | 可爱形象、可自定义模型、低打扰 |

### 1.3 设计原则

1. **录入零成本**：一句话、一个快捷键就能新增计划（自然语言解析优先，表单兜底）。
2. **本地优先（Local-first）**：默认全部数据在本地，离线可用；同步是可选项。
3. **排程可解释、可干预**：AI 排完用户能看懂为什么这样排，能拖拽微调，系统从中学习偏好。
4. **低打扰**：小人默认安静，提醒走气泡/系统通知；用户可通过强度参数控制"催促力度"。

## 二、核心功能模块划分

整体分为六层（见架构图）：

```
┌────────────────────────────────────────────────────┐
│  ① 形象交互层（桌面小人）                            │
│     Sprite/Live2D 渲染 · 气泡对话 · 拖拽互动 · 提醒演出 │
├────────────────────────────────────────────────────┤
│  ② 录入层（计划捕获）                                │
│     快捷键浮窗 · 自然语言解析 · 手动表单 · 剪贴板监听   │
├────────────────────────────────────────────────────┤
│  ③ 排程引擎层（核心）                                │
│     课表管理 · 强度参数 · 约束求解/评分 · 增量重排     │
├────────────────────────────────────────────────────┤
│  ④ 数据层                                           │
│     本地 SQLite/IndexedDB · 变更日志 · 同步队列        │
├────────────────────────────────────────────────────┤
│  ⑤ 服务与集成层                                     │
│     系统托盘 · 通知 · 开机自启 · 日历导入(ICS) · AI 接口│
├────────────────────────────────────────────────────┤
│  ⑥ 同步层（可选）                                    │
│     端到端加密同步 · WebDAV/自建轻后端 · 手机端只读+轻编辑│
└────────────────────────────────────────────────────┘
```

### 模块 1：形象交互层（桌面小人）

- **渲染**：透明无边框置顶窗口；两种技术路线——轻量 Sprite 序列帧（成本最低）或 Live2D（表现力最强，参考"小美同学/charlotty"）。
- **状态机**：待机 / 工作（对应用户当前计划，做"打字、翻书"等动作）/ 提醒 / 休息 / 庆祝（完成任务）/ 失落（超时未完成，但语气克制）。
- **行为联动**（差异点）：小人动作与排程状态绑定——到点进入计划时小人切换"工作"动画并冒出小气泡"开始学英语啦 30 分钟"；空闲时段小人散步。
- **交互**：单击展开环形菜单/主面板（今日日程、快速新增）；拖拽移动；右键托盘菜单；全局热键唤起。
- **窗口穿透**：小人区域默认鼠标穿透可开关，避免挡操作（BongoCat 已验证该体验）。

### 模块 2：录入层（计划捕获）

- **快捷键浮窗**：全局热键（如 Ctrl+Alt+N）唤起输入条，输入"周四之前把实验报告写完，大概要 3 小时"。
- **自然语言解析**：抽取实体——标题、预估时长、截止时间（DDL）、优先级、是否可拆分、地点约束。技术方向：优先本地小模型/规则正则兜底，云端 LLM 增强解析（可配 API Key，也支持 Ollama 本地模型，参考 desktop-pet 的本地/云双路由）。
- **解析结果确认卡**：不直接入库，弹出确认卡（一句话 + 结构化字段预览），用户回车确认——保证"自动录入"但不"自动出错"。
- **固定事件导入**：支持导入 ICS 日历文件 / 复制粘贴课表文本识别（教务系统课表格式规则化解析），生成"不可移动"的固定块。

### 模块 3：排程引擎层（核心，见第四节详细逻辑）

- **课表管理**：周期性固定事件（上课、例会、睡眠），区分学期周期与单周例外。
- **强度参数面板**：用户可动态调节的"负荷旋钮"，包括：
  - 每日总负荷上限（如学习类 ≤ 6h/天）；
  - 单块时长上限/下限（如单块 25min～90min）；
  - 连续工作上限与最小休息间隔（番茄/90 分钟节律）；
  - 精力曲线偏好（早起型/夜猫型，各时段的"精力权重"）;
  - 各类别每日配额（如英语 1h、健身 0.5h）。
- **排程与重排**：新增/完成/超时/参数变更时增量重算当日及未来日程；夜间低峰期跑一次全局优化。

### 模块 4：数据层

- 本地单文件数据库（SQLite / IndexedDB），所有写操作追加**变更日志（changelog）**，作为同步与撤销的基础。
- 计划状态机：草稿 → 已排布 → 进行中 → 完成/超时顺延/取消。

### 模块 5：服务与集成层

- 系统托盘、系统通知、开机自启、单实例锁。
- 番茄钟/专注计时（可选）：开始计划时自动计时，超时检测驱动重排。
- 统计复盘：时间去向报表、排程命中率（实际执行/计划之比），反哺精力曲线参数。

### 模块 6：同步层（见第六节方案）

## 三、数据模型（实体关系）

核心实体六个，围绕「计划 Task」与「时间块 Block」分离设计——**任务是"要做什么"，时间块是"什么时候做"**，这是自动重排的关键（任务不动，块可整体重排）：

| 实体 | 关键字段（思路级） | 说明 |
|---|---|---|
| **Task 计划** | id、标题、类别、预估时长、DDL、优先级、可拆分性（能否切成小块）、最小块长、地点约束、依赖（须在 X 之后）、状态 | 录入层产出 |
| **Block 时间块** | id、task_id、开始、结束、类型（固定/弹性/休息/缓冲）、锁定标记 | 排程引擎产出；用户拖拽后打"锁定"标记，重排时不动 |
| **FixedEvent 固定事件** | 标题、重复规则（RRULE 思路）、生效周期、例外日期 | 课表、例会、睡眠 |
| **IntensityProfile 强度参数** | 日负荷上限、块长上下限、最小休息、精力曲线（24h 权重向量）、类别配额、催促力度 | 用户动态可调，带"生效日期"支持历史复现 |
| **ExecutionLog 执行记录** | block_id、实际开始/结束、完成度 | 用于统计与参数学习 |
| **ChangeLog 变更日志** | 序号、实体、操作、时间戳、设备标识 | 同步与撤销的基础，单向追加 |

关系要点：
- Task : Block = 1 : N（长任务拆多块，块上记录进度比例）；
- Block 生成时快照当时的强度参数版本，便于复盘"当时为什么这样排"；
- ChangeLog 是唯一同步单位，实体表不直接同步（见第六节）。

## 四、排布调度逻辑（核心算法思路）

### 4.1 问题建模

本质是**带约束的时间块分配问题**：给定任务集合（含时长、DDL、优先级）、固定事件（课表）、强度约束，在剩余自由时间里切分并放置时间块，使"总效用"最大且约束全部满足。

分两层实现，由浅入深：

### 4.2 第一层：贪心 + 评分（MVP 版本，参考 notioncal 的思路）

1. **构造空闲槽位**：从课表固定事件中挖去已占用时间，得到当日/未来若干自由时段。
2. **候选放置点评分**，每个（任务 × 空闲槽）打分，分高者优先放置：
   - DDL 紧迫度（越近权重越高）；
   - 优先级；
   - 精力匹配度（任务类别 × 该时段精力权重，如"刷题"配上午高精力段）；
   - 碎片适配度（剩余槽长与所需块长的贴合程度）;
   - 多样性惩罚（避免一整天连续同一任务，参考 notioncal 的防长块设计）。
3. **放置校验**：放置后检查强度约束（日负荷上限、连续时长、最小休息），不满足则切分或顺延。
4. **排不下报警**：DDL 前容量不足时提前预警（"周四前写不完实验报告，建议每天加 40 分钟或申请延期"）。

### 4.3 第二层：约束求解优化（进阶版本）

- 建模为约束满足/优化问题，用 **OR-Tools CP-SAT**（参考 Adaptive AI Scheduler 的做法）或 Java 侧 OptaPlanner（tcPlanner 的思路）求解：硬约束（不重叠、不进课表、不超负荷）+ 软约束（精力匹配、偏好时段、间隔休息）加权最大化。
- 求解器在后台异步运行：先出可行解立即展示，持续优化替换更优解（"先快后好"策略，tcPlanner 已验证此体验可行）。

### 4.4 增量重排与冲突处理（体验关键）

- **触发**：新增计划、手动拖拽、任务超时、强度参数调整、固定事件变更。
- **原则**：只重排"未开始且未锁定"的块；已开始/已完成的块不动；用户手动拖过的块默认加锁。
- **超时顺延**：某块未按时完成 → 该任务剩余时长重新入队，优先占用最近的低价值空闲槽，并触发受影响 DDL 的容量复检。
- **学习闭环**：ExecutionLog 记录实际执行 vs 计划，长期统计用户"上午实际效率高/经常拖到晚上"，自动微调精力曲线参数（先做简单规则统计，后续可引入 Prophet 类时序模型做时段效用评分）。

### 4.5 人机协同

- 排程结果以"建议稿"呈现，用户可一键采纳或拖拽微调；
- 拖拽行为被记录为偏好信号（用户总把英语从早上拖到晚上 → 更新偏好权重）。

## 五、技术实现方向

| 层面 | 推荐方案 | 理由 |
|---|---|---|
| **桌面框架** | 首选 **Tauri 2**（Rust + WebView）；备选 Electron | Tauri 内存占用小、天然适合常驻桌宠；BongoCat（Tauri 重写版）已验证跨平台透明窗口+穿透可行。Electron 生态更熟、排程逻辑可用 TS 共享到手机端 |
| **小人渲染** | 起步用 Sprite 序列帧（Pixi.js）；进阶 Live2D Cubism SDK | Sprite 成本低、素材社区多；Live2D 参考小美同学（charlotty）方案 |
| **排程引擎** | 与 UI 分离的独立模块（TS 或 Rust），MVP 用贪心评分，进阶接 OR-Tools（Python 边车进程） | 保持引擎纯函数化、可单元测试、可被手机端复用 |
| **数据** | SQLite（Tauri）或 IndexedDB（Electron），+ ChangeLog 追加表 | 单文件、可备份、同步友好 |
| **AI 解析** | 双路由：本地规则+小模型兜底；可配 LLM API / Ollama 本地模型 | 离线可用、隐私可控（desktop-pet 模式） |
| **系统集成** | 托盘、全局热键、通知、开机自启、窗口穿透 | 桌宠类产品标配 |
| **分发** | GitHub Releases + 安装包（MSI/NSIS）+ 绿色免安装包 | 参考 charlotty 的双分发方式 |

### 模块间通信

UI（WebView）↔ 主进程（Rust/Node）通过命令 + 事件双向通信；排程引擎作为独立服务模块，对外暴露「重算日程」纯接口；同步模块只消费 ChangeLog。

## 六、与手机端的数据同步方案

### 6.1 手机端定位

手机端做**轻客户端**：查看今日日程、快速新增（语音/文字）、勾选完成、接收提醒——不做完整排程编辑，重排仍在桌面端主设备完成。

### 6.2 推荐架构：本地优先 + ChangeLog 同步（三级演进）

**级别 1（起步）：文件级同步**
- 数据库变更导出为追加式 JSONL 变更文件，通过 **WebDAV / 坚果云 / Dropbox** 同步（Super Productivity 已验证 WebDAV/Dropbox 方案成熟、零服务器成本）。
- 双端各自回放 ChangeLog 合并；冲突按"时间戳 + 实体级 last-write-wins"初版处理。

**级别 2（正式）：端到端加密同步服务**
- 自建轻量同步服务（或用 Supabase/云函数），只存加密后的 ChangeLog 分片，密钥由用户设备派生（SuperSync 的端到端加密 + 可自托管思路）。
- 设备配对：手机扫码绑定，交换密钥。

**级别 3（进阶）：CRDT 合并**
- 计划/块数据结构改为 CRDT（如 Yjs 文档），多端并发编辑自动无冲突合并，适合未来"手机端也能完整编辑"的扩展。

### 6.3 冲突与一致性要点

- 同步单位是 ChangeLog 条目而非整库，天然支持断点续传与离线积累；
- 排程结果（Block 表）**不同步原始排布，只同步"任务 + 参数 + 锁定块"**，各端各自重算排布——避免双端排布互相打架（这是本方案的关键设计：排布是派生数据，不是事实数据）；
- 提醒在手机端本地触发（系统通知），不依赖桌面端在线。

| **奇妙日程 / Timely / TimeMind 等 AI 排程 App** | AI 排期普遍做法：自然语言录入 → 生成方案预览 → 用户确认再入库 → 计划有变一键重排；"每日成果回执"分享图是传播点 |

**创意融合点**：把 AI 排程 App 的"预览-确认-重排"流程，用小人的演出呈现——排完日程小人"搬着时间块"动画摆进日历；超时顺延时小人表现出"着急收拾"的动作。情感化包装排程引擎，这是 B 站传播的核心素材。

## 九、开源准备建议

1. **仓库结构**：核心排程引擎独立成包（可被手机端复用），形象渲染、UI、同步分模块；排程引擎配套纯逻辑单元测试（贪心评分、约束校验、增量重排用例）。
2. **协议与资产**：代码 MIT；小人素材/模型格式单独定义开放规范（JSON manifest + 贴图包），鼓励社区二创（学 Awesome-BongoCat 生态）。
3. **Roadmap 分期**：
   - v0.1：小人 + 手动计划 + 课表导入 + 贪心排程（单机）；
   - v0.2：自然语言录入（规则+LLM 双路由）+ 强度参数面板 + 增量重排；
   - v0.3：WebDAV 同步 + 手机端轻客户端；
   - v0.4：约束求解器 + 执行日志学习偏好 + 模型生态规范。
4. **文档**：README 用动图展示"一句话新增 → 自动排进课表缝隙"的核心 10 秒体验；设计文档（即本文）入 `docs/`。
5. **合规提醒**：Live2D Cubism SDK 有单独授权条款，开源分发需确认；若接教务系统课表，只做用户本地文本解析、不爬取。

## 十、风险与待决问题

- **排程可解释性**：求解器给出的结果用户可能"看不懂为什么"，需在 UI 附理由摘要（"因为明天有 DDL 且你上午精力分最高"）。
- **过度自动化反弹**：用户可能抗拒完全自动的排布，保留"建议稿 + 确认"模式作为默认。
- **LLM 依赖成本**：自然语言解析若全走云端 API 有费用与隐私顾虑，必须保留本地规则兜底。
- **同步冲突边界**：排布派生数据不同步的策略能规避大部分冲突，但"锁定块"的跨端语义需在 v0.3 详细设计。
